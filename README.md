# 宿舍 · 四个位置，一起生活

以中国大学四人寝「上床下桌」为布局原型的交互式 3D 用电可视化。左右各两个独立床位，中央通道；每床一张上铺、一张书桌、一把椅子、储物柜、梯子和独立四孔插排。

## 四个床位

| 床位 | 主题       | 独立插排的四件设备                     |
| ---- | ---------- | -------------------------------------- |
| 01   | 数字工作站 | 游戏笔记本、台灯、iPhone、平板 |
| 02   | 音乐与阅读 | MacBook、台灯、安卓手机（一个插位空置） |
| 03   | 灵感设计室 | 游戏笔记本、台灯、iPhone、平板 |
| 04   | 轻松生活角 | MacBook、台灯、安卓手机（一个插位空置） |

- 点击床架/书桌或全寝面板的床位列表进入该位置，也可按 1–4。
- 每床四孔一孔一设备；关闭某床位插排只影响该床位，全寝总电源控制上游。
- 默认面板隐藏。点设备查看独立功率、负载、累计耗电与曲线；点插排查看该床位四个插孔。
- 进入床位时上铺自动淡出，避免遮挡桌面；查看上铺或返回全景时自动恢复。
- 提供「近看插头与走线」「近看上铺与护栏」及每件电器聚焦。
- 日夜切换、四路能流；窄屏为可滚动、可展开的底部抽屉。

## 模型展板式交互界面

- 顶栏统一返回全景、日夜和全寝用电入口；暖灰外框内嵌场景，蓝色用于当前选择与数据。设计说明见 [DESIGN.md](DESIGN.md)。
- 左下角功率卡默认收起，点击展开趋势与累计耗电；右侧工具栏集中镜头、能流、标签与交互指南。
- 仅场景工具条保留 Liquid Glass React，菜单使用少量磨砂。按钮、功率读数和详情采用稳定的实色表面；日夜配色同步。
- 1024px 及以上使用 352px 侧栏，更窄时使用半高/四分之三高底部抽屉。设备电源与负载直接显示在详情首屏。
- 场景标签显示选中设备全名，其余以插孔编号定位；投影避让和连接线避免标签互相遮挡。
- “当前”与“24 小时记录”独立查看，功率显示共用精度规则。“24 小时记录”的曲线支持指针选点、持续显示读数、方向键和时间滑块。
- 全寝面板的「24 小时记录」只展示已建模的 6 类设备及其合计，按平均功率降序排列，点选切换曲线；设备面板显示对应组的单台均分曲线。
- 所有二维控件直接使用 [shadcn/ui](https://ui.shadcn.com/) 官方组件，包含场景标记、详情 Sheet、开关、滑块、进度条、工具提示与加载状态。功率曲线是唯一自绘原语（`src/components/ui/sparkline.tsx`），理由见 [UI 规范](docs/ui-system.md)。
- 配色、间距、圆角与焦点尺寸集中在 `src/index.css` 的全局 Tailwind / shadcn 变量；业务层只组合组件与标准工具类，不写控件 CSS 或内联视觉样式。
- `npm run check:ui` 检查业务层组件规范；`npm run check:interaction` 检查标签碰撞、边界、数字和面板状态，CI 同步执行。

## 建模与检查

模型使用本地程序化几何与纹理，不下载第三方模型；唯一的外部资源是一张 CC0 的 HDRI 环境贴图（见下）。床架含立柱、横梁、护栏、连接螺钉、梯子踏步；书桌含背板、支撑、柜格、板厚、把手、锁芯、理线夹。设备建模包括屏幕边框/铰链、支座、风扇网罩、机箱格栅、纸槽、耳机支架与实际插头接触位置。

已逐床位截取并查看近景，同时单独查看上铺、插排、主机、打印机。设备几何包围盒用于检查桌面越界、柜格净空、支撑面接触、同床位设备相互重叠。检查内容和发现后修复的问题见 `docs/model-inspection.md`。

表面材质在 `src/scene/materials.ts` 里程序化生成，每个表面（木、织物、墙面、喷漆、哑光漆）同时产出颜色、法线、粗糙度三张 512² 图，颜色图保持中性，色相仍由构件的 `color` 决定，所以换配色不需要重做贴图。

纹理坐标不走模型自带的 UV：`StaticGeometry.tsx` 在按材质合批前，用法线主轴向把顶点位置投影成 UV（单位米，`TILE` 决定一张贴图覆盖多少米）。原始 UV 在 `boxGeometry` 与 `RoundedBox` 之间基向量并不一致，直接缩放会让木纹方向在不同构件间翻转；投影之后桌面、桌沿、搁板的颗粒大小一致，顺纹方向也始终沿着构件最长的那个面轴。投影放在合并坐标系里算，同一床位内的相邻构件纹路接得上，地砖之间又各不相同。

因为 UV 会重复很多次，噪声改用带周期的 `pnoise`/`pfbm`（周期取整数、每层频率翻倍时周期同步翻倍），否则每个 tile 边界都会留下网格状接缝。木纹的尺度是按「总览距离下还读得出来」定的：一张 0.75 米贴图里铺 3 块板，板缝约 8mm、年轮约 6cm；再细的线会被 mipmap 平均成一片糊（这一版之前板缝只有 1.8 像素宽，实测在总览里完全看不见）。

环境光来自一张真实的 HDRI：`src/assets/env/brown_studio_1k.hdr`，Poly Haven 的 `brown_photostudio_02`（CC0，1k，约 1.6 MB）。黑漆柜体、桌面这类低粗糙度表面靠它拿到真实的高光与反射层次——只用点光和平行光时它们会呈现为一片死黑。HDRI 解码前用 Lightformer 搭的临时环境顶上，避免首帧发黑。换成真实环境光后，`ambientLight` 从 1.2 降到 0.62、`hemisphereLight` 从 0.8 降到 0.38、主光从 2.8 降到 2.15，否则墙面会过曝。

柜体配色：侧壁与上下封板为近黑哑光漆 `#31383f`，上下两扇柜门为蓝 `#4b82b8`，柜内背板保留浅色。蓝色取偏亮一档，因为柜体常年处在书桌阴影里，深蓝会读成黑色；侧壁不用纯黑，纯黑配合低粗糙度在环境光下缺少中间层次。

建筑侧墙与桌后板使用剖面表达；不把剖面图当作完整封闭建筑。进入桌面视角时上铺会自动淡出以减少遮挡。

## 开发和预览

```bash
npm ci
npm run dev        # 0.0.0.0:46340 / HMR

npm run lint

```

```bash
systemctl status power-strip-dev
systemctl restart power-strip-dev
journalctl -u power-strip-dev -f
```

## GitHub Pages 自动构建

生产站点：`https://kernel4632.github.io/power-strip/`。

- 推送到 `main` 自动执行锁文件安装、lint（警告视为失败）、TypeScript 检查、生产构建与 Pages 部署。
- 面向 `main` 的 Pull Request 只运行检查和构建，不部署，且不获取 Pages 写权限。
- 可在 Actions 中手动运行 `Build and deploy GitHub Pages`；发布只允许 `main`。
- 工作流使用 GitHub 官方 Actions 并固定提交 SHA，部署使用自动签发的 `GITHUB_TOKEN`，无需额外 PAT 或仓库密钥。
- Pages 产物只包含 `dist/`，不发布源码目录或开发服务。

```bash
npm run build:pages  # /power-strip/ 子路径构建
npm run preview -- --base=/power-strip/
```

普通 `npm run build` 与 `46340` 开发预览继续使用根路径。Pages 是生产构建：修改代码后需提交并推送，等 Actions 成功才更新，不提供开发 HMR。重命名仓库或改用自定义域名时，应同步调整 `build:pages` 中的基础路径。

## 数据来源与计算

三份小组分享的 Excel 是数值来源。2026-10-22 已核对本地附件与群内发送文件的内容校验值。原文件及聊天记录不提交仓库；生成模块记录文件名、SHA256、工作表和范围。详见 [数据核对记录](docs/data-sources.md)。

```bash
python scripts/import-workbooks.py --power <24小时汇总表.xlsx> --strips <排插数据.xlsx> --devices <设备功率数据表.xlsx>
npm run check:data
```

- 导入 12 类设备、每类 144 个十分钟区间，以及 12 款插排。00:00–23:50 参与累计，24:00 不重复计入。输入有缺失、列名错位或汇总不符会报错。
- 网站按建模清单筛选数据，6 类、14 台设备当日累计 3.361167 kWh，同时段合计峰值 590 W。「24 小时记录」的合计曲线、平均功率、峰值与日耗电均按此范围重算，不受本次开关影响。
- 场景是 14 台桌面设备：MacBook ×2、游戏笔记本 ×2、iPhone ×2、安卓手机 ×2、平板 ×2、台灯 ×4。每组原表只有合计，没有单机记录。每台 100% 负载改用设备资料表的单台参考功率（MacBook 35 W、游戏笔记本 230 W、台灯 10 W 等），逐台可查；原表的组记录合计只用于「24 小时记录」曲线。
- 一号、三号床位各为游戏笔记本、iPhone、台灯、平板；二号、四号为 MacBook、安卓手机、台灯。未有数据的显示器、主机、风扇等不再充当耗电设备。
- 空调、洗衣机、LED 照明、热水壶、吹风机、电煮锅不在现有模型中，已从网站的记录列表和统计中排除。完整导入数据仅保留用于来源核对，不为用齐数据增加模型。
- 当前读数不绑定北京时间。恢复提交 `3746e49` 的交互模拟：目标功率 = 单台参考功率 × 负载比例 × (0.97 + 0.03 × sin(会话秒数 × 0.7 + 设备序号 × 2))，按 1 − exp(−dt × 2.5) 平滑追随。滑块调整负载水平，松手后仍持续小幅波动；各设备相位不同。例如 MacBook 50% 的参考上限为 17.5 W，稳定运行时在其 94%～100% 范围内波动。关闭设备或上级电源立即归零。14 台参考功率合计仍为 804 W，运行合计随波动变化。界面标题为「本次功率」，这些秒级波动不是采集值；24 小时记录仍为独立的原始数据。
- 原表说明不保证所有原始记录都是独立实测，界面使用「记录」命名。
- 参考设备型号和单台运行 / 参考功率取自设备资料表主表，不采用其残留旧值的「海报制图数据」页。只展示已建模设备的资料；界面的功率一律以这一列为基准，时序记录峰值只出现在「24 小时记录」，两处互不覆盖，例如游戏本资料为 230 W，其组记录均分峰值为 200 W。
- 设备、插排和总开关控制本次场景供电；负载比例只调整本次读数，不改历史记录。关闭即按零功率计算，不沿用未经记录的待机值。模型亮屏/灯光、能流跟随实际非零功率。
- 「本次用电」按 `3746e49` 的梯形累计方式计算：前后两次功率均值 × 间隔秒数 / 3600 得到 Wh，显示时除以 1000，固定保留四位小数 kWh。从打开网页起计时，刷新清零；保留单调时钟、完整间隔及控制事件前结算，不恢复旧版最多累计 5 秒的截断；「日耗电」按 144 个区间求和除以 6000 得到 kWh。两者分开展示。
- 「本次功率」恢复展示本次交互曲线：负载滑块、设备/插排/总开关立即采样，另每秒采样一次，保留最近 90 个点；横轴按实际采样时间排布，纵轴固定为所选设备或合计的参考功率量程。它不修改「24 小时记录」；波动使用上述可复现的旧版正弦算法，不使用随机数。曲线紧接负载控件，不再增加一条时间滑块。
- 四个桌面插排采用表中「公牛407四插位」作为参考规格：2500 W、214×53×31 mm、29.8 元。模型仍是示意外形，不声称精确复刻该商品。孔数保留源表原文，14 孔不是 14 个插位。网站只展示这一款对应资料。
- 表中没有宿舍总回路上限，因此移除原先 2200 W 的默认告警阈值；床位插排上限使用参考规格 2500 W。
